# uad — віджети для кабінету Асоціації (ua-developers.com.ua)

Три самодостатні JS-віджети, які вставляються у Webflow через HTML Embed:

| Файл | Що це | Теги |
|---|---|---|
| `uaofd-roadmap.js` | Дорожня карта врегулювання (вкладка «Юридичний напрямок») | `v2` … `v9` (останній — `v9`) |
| `uaofd-finance.js` | Фінансові показники | `fin-v1` … `fin-v4` |
| `uaofd-memorial.js` | Меморіал Героїв Небесної Сотні (+ `memorial-imgs/`) | `mem-v1` … `mem-v5` |
| `apps-script/Code.gs` | Бекенд-скрипт Google Apps Script (Таблиця → JSON) для дорожньої карти | — |

Нижче — головне про **дорожню карту** (`uaofd-roadmap.js`): як вона працює, як її оновлювати й викочувати на сайт.

---

## 1. Як це працює (повний ланцюжок)

```
Webflow (HTML Embed на сторінці /cabinet/dashboard, пароль на сторінці)
   │  <div data-uad-roadmap></div>
   │  <script src="https://cdn.jsdelivr.net/gh/pavlokot/uad@vN/uaofd-roadmap.js" defer>
   ▼
jsDelivr CDN  ← віддає файл із цього GitHub-репозиторію за ТЕГОМ vN
   ▼
uaofd-roadmap.js (у браузері відвідувача)
   • монтується у Shadow DOM (стилі сайту й віджета не чіпають одне одного)
   • малює: плитки-підсумки, прогрес, легенду, фільтри, картки «проблема → рішення» з 6 етапами
   • дані бере з ОДНОГО з двох джерел (див. нижче)
```

**Чому зовнішній файл, а не код прямо в Webflow:** HTML Embed у Webflow обмежений ~10 000 символів, а віджет ~45 КБ.

### Два джерела даних

1. **Вбудована копія** — масив `SECTIONS_DEFAULT` усередині `uaofd-roadmap.js`. Показується завжди, якщо немає `data-src` або таблиця недоступна.
2. **Жива Google-таблиця** — якщо на `<div>` є `data-src="URL_Apps_Script/exec"`, віджет при завантаженні сторінки тягне свіжий JSON з таблиці (`apps-script/Code.gs`), малює його поверх вбудованої копії і зберігає останній успішний знімок у `localStorage` браузера.

> **Поточний стан:** `data-src` у Webflow **не налаштований** (там була заглушка), тож сайт показує **вбудовану копію**. Працюємо в ручному режимі — див. розділ 3. Щоб перейти на живу таблицю, див. розділ 6.

### Формат даних (`SECTIONS_DEFAULT`)

```js
{ t: "Назва розділу",                 // номер додається автоматично за порядком
  note: "Спільна проблема для кількох пунктів",   // необов'язково
  items: [                            // або subs: [{ t: "6.1. Підрозділ", items: [...] }]
    { p: "Проблема", r: "Рішення", st: "gggo.." },
    { p: "Проблема", rLead: "Вступ:", rList: ["пункт 1", "пункт 2"], st: "oo...." },  // рішення списком
    { solo: true, sh: "", r: "щодо зон охорони", st: "gggggg" }                       // пункт без власної проблеми (під note)
  ] }
```

`st` — рядок із **6 символів**, по одному на етап (колонки C–H таблиці):
`g` = 🟢 етап опрацьовано · `o` = 🟠 у роботі · `.` = ⚪ попереду.
Етапи: 1 звернення до профільного органу → 2 концепція НПА → 3 погодження → 4 розгляд за регламентом → 5 погоджений проєкт → 6 рішення ВР/КМУ/ОМС.

Плитки, відсоток прогресу й лічильники фільтрів рахуються з `st` автоматично — руками їх не правимо.

## 3. Процес оновлення дорожньої карти (ручний режим)

Джерело правди — Google-таблиця «Юридичний напрямок: задачі в роботі» (аркуш «Аркуш1»). Хтось надсилає зміни (скріншоти рядків, нові пункти, змінені кружечки) → вносимо їх у `SECTIONS_DEFAULT`.

1. **Клон / актуалізація**
   ```bash
   gh repo clone pavlokot/uad && cd uad   # або: git pull origin main
   ```
2. **Редагування** `uaofd-roadmap.js`, масив `SECTIONS_DEFAULT`:
   - новий пункт — додати об'єкт у `items` потрібного розділу (порядок як у таблиці);
   - зміна статусу — поправити рядок `st`;
   - текст беремо дослівно з таблиці (апостроф — `’`).
3. **Перевірка синтаксису**
   ```bash
   node -c uaofd-roadmap.js
   ```
4. **Локальна перевірка (за потреби)** — підняти `python3 -m http.server`, відкрити тестову сторінку з `<div data-uad-roadmap>` і `<script src="/uaofd-roadmap.js">`, глянути лічильники плиток і картки.
5. **Коміт і пуш у `main`**
   ```bash
   git add uaofd-roadmap.js
   git commit -m "Roadmap: <що змінилось>"
   git push origin main
   ```
6. **Новий тег версії** (наступний після останнього — зараз `v9` → `v10`):
   ```bash
   git tag -a v10 -m "Roadmap v10: <що змінилось>"
   git push origin v10
   ```
7. **Перевірка на CDN** (тег доступний одразу, кешу немає):
   ```bash
   curl -s https://cdn.jsdelivr.net/gh/pavlokot/uad@v10/uaofd-roadmap.js | grep -c "<унікальний фрагмент нового тексту>"
   ```
8. **Деплой на сайт** — у Webflow у HTML Embed дорожньої карти змінити тег у `<script src>` з `@v9` на `@v10` → **Publish** сайту.
   Дивитись результат треба на **опублікованій** сторінці (у Designer/Preview скрипти з Embed зазвичай не виконуються), у вікні з паролем сторінки.

### Чому саме теги, а не `@main`

jsDelivr кешує `@main` на години, а purge (`purge.jsdelivr.net/...`) має ліміт: після кількох викликів відповідає `finished`, але реально не чистить (`throttled: true`, ~47 хв). Тег — це нова адреса без кешу, тож **кожен реліз = новий тег**. Старі теги не чіпаємо (незмінні) — це й відкат: щоб повернутись, у Webflow ставимо попередній тег.

## 4. Embed-код для Webflow

```html
<div data-uad-roadmap></div>
<script src="https://cdn.jsdelivr.net/gh/pavlokot/uad@v9/uaofd-roadmap.js" defer></script>
```

Необов'язкові атрибути на `<div>`:

| Атрибут | Для чого |
|---|---|
| `data-src` | URL Apps Script `/exec` — живі дані з таблиці (див. розділ 6) |
| `data-ttl` | хвилини кешу в браузері відвідувача (`1440` = раз на добу); без нього — свіже щоразу |
| `data-key` | секретний ключ, має збігатися з `ACCESS_KEY` у `Code.gs` |
| `data-bg` | колір фону під блоком (за замовчуванням `#f5f5f5`) |

Віджет сам домонтовується, якщо гейт (Webflow-пароль / MemberSpace) показав блок пізніше.

## 5. Стиль і підводні камені

- **Кольори (брендбук):** фіолетовий `#85529C`, наві `#1B3155`, зелений `#3E9536`, оливково-жовтий `#D1CE05`, рудий `#D3411C`. Активний фільтр — фіолетовий. Тло — `#f5f5f5` (підтверджено піпеткою на сайті; брендовий `#F9F7F5` не підійшов).
- **Шрифт:** звичайний `Arial`-стек. Спроба поставити `Mark Simonson Proxima Nova` не спрацювала (на сторінці не резолвиться) — відкотили. Перед будь-якою зміною шрифту — перевірка *візуально*, а не за рядком `font-family` з DOM.
- **Відступи:** віджет не має власних зовнішніх відступів; лише внутрішній `padding: 32px 40px 40px`, підігнаний під ліву межу табів (60px від краю сторінки).
- **CSS у файлі — це JS-рядок.** Якщо вставляєте шрифти чи лапки — екрануйте `"` як `\"` або використовуйте `'…'`, інакше файл перестане парситись. Завжди `node -c` перед комітом.
- **Не міняти сліпо у всіх трьох віджетах одразу** — спершу показати на одному.
- Сторінка `/cabinet/dashboard` закрита паролем Webflow (Restrict access). Старі редиректи/сторінка `dashboard-old` видалені; 401 на прямому запиті — це нормальна форма пароля.

## 6. Перехід на живу таблицю (коли знадобиться)

1. У Google-таблиці: **Розширення → Apps Script** → вставити `apps-script/Code.gs` → зберегти.
2. **Розгорнути → Новий розгортання → Веб-застосунок** (виконувати від себе, доступ — будь-хто) → скопіювати URL на `/exec`.
3. Перевірити URL у браузері — має віддавати JSON з 11+ розділами.
4. У Webflow Embed додати `data-src="ТОЙ_URL"` (і за потреби `data-key`, якщо в `Code.gs` задано `ACCESS_KEY`).
5. Після цього правки достатньо робити лише в таблиці; вбудовану копію оновлюємо рідко, як запасну.

`Code.gs` читає аркуш «Аркуш1» як є: рядки-розділи `N. Назва` у колонці A, підрозділи `N.M.`, статуси в C–H (🟢/🟠/⚪), об'єднана клітинка зі спільною проблемою (→ `note` + `solo`-пункти), маркований список у «рішенні» (→ `rLead`/`rList`).
